# Hard constraints

1. **Remote-first.** 2 of the 4 members are remote. Prefer software-only projects. Each remote member must own a full workstream that needs no physical parts.
2. **Software only (Neil, Tue Nov 17): we cannot get parts in time.** Household items already on hand (a fan, a fridge, a straw, the team's own phones and laptops) may appear in the demo as props. The old hybrid rule below is kept for reference only.

   **Old rule. Hybrid (software plus hardware) was allowed only if all of these hold:**
   - Every part can be obtained by **Friday Nov 20**, from local stock (Micro Center Fairfax, GMU makerspaces and labs, the teammates' parts bins) or online (Amazon Prime 1-day). This is the team's stated limit. Because the build days are Tue–Wed, **parts should be in hand by Tue Nov 17 evening**. A part that arrives Friday leaves no time to test.
   - **No major bottleneck.** The software must run, and be demo-able, with a simulated or mocked device. The hardware is an upgrade to the demo, not a dependency.
   - The local members hold the parts. The remote members build against a device API or simulator that the local members define on day 1.
   - It must show well on camera, because judging is virtual.
3. **Fit the track:** Life underground (the Hollow). Address several of the 15 problems in `context/track.md` with one connected solution, and name the problem numbers in the pitch.
4. **Ethics:** tools for surveillance, scraping, or "the resistance" must be **defensive and consent-based**. Scan only yourself, or data you have permission to use. Do not deanonymize, track, or target real people. Judges reward responsibility, and a project that does this can be disqualified.
5. **Make it demo-able on video.** Judging is almost certainly asynchronous (Nov 21–24), so the submitted video is the demo. Keep it runnable live in case there is a call. Seed the data so the demo never depends on luck.
